SIMPLE_ENCRYPTION

Simple encryption and hashing for Eiffel

Overview Quick Start API Reference Security GitHub

Overview

SIMPLE_ENCRYPTION provides secure hashing and password management for Eiffel applications: Windows CNG (bcrypt.dll) natively, and a corrected portable path over the ISE EEL primitives elsewhere. Use 2.0.0 or later - see the security advisory below.

Key Features

  • SHA-256 hashing
  • HMAC-SHA256 message authentication
  • PBKDF2 password hashing
  • Secure password verification
  • Random token generation from the OS CSPRNG - no PRNG fallback
  • 2.0.0: native CNG backend (BCryptHash, BCryptDeriveKeyPBKDF2, BCryptGenRandom); is_native and is_secure_random_available report which path is live

Quick Start

<library name="simple_encryption" location="$SIMPLE_ENCRYPTION/simple_encryption.ecf"/>

Password Hashing

local
    enc: SIMPLE_ENCRYPTION
    stored_hash: STRING
do
    create enc.make

    -- Hash password for storage
    stored_hash := enc.hash_password ("user_password")
    -- Returns: salt$iterations$hash

    -- Verify password
    if enc.verify_password ("user_password", stored_hash) then
        print ("Access granted%N")
    end
end

SHA-256 Hashing

hash := enc.sha256 ("data to hash")
-- Returns 64-character hex string

Security Notes

  • PBKDF2 uses 600,000 iterations by default (OWASP 2025)
  • Password verification uses constant-time comparison
  • Security advisory, 2.0.0 (2026-08-29): before 2.0.0, PBKDF2 diverged from RFC 8018 from iteration 119 onward and HMAC-SHA256 dropped a leading zero byte once in 256 (an as_bytes defect in the EEL layer), and random bytes were time-seeded. 2.0.0 fixes all three, verified against RFC 7914 vectors and independent test vectors; hashes made by earlier versions must be regenerated. Full statement in the README and CHANGELOG.
  • Random bytes come from the OS (BCryptGenRandom on Windows, /dev/urandom elsewhere); there is no PRNG fallback
